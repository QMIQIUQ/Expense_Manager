# 收入與預算聯動：檢查結果與實作計畫

日期：2026-10-23。狀態：功能已實作並完成本機驗證；main 發布及部署狀態另以工作流程結果確認。

## 1. 目的與交付邊界

讓使用者選擇以「本期已入帳收入 × 自訂比例」作為每月預算的資金來源，保留既有手動預算。
收入增加時增加尚可分配額度；收入減少時顯示資金缺口，保留分類預算。
此文件描述預期行為、現況依據、必要修改及驗收條件；文件存在不表示功能已上線。
使用者已確認交付範圍為計畫後接續實作、驗證，再推到 main；本文件保留原檢查依據並記錄實作結果。

首版範圍為實際收入、每月帳單週期、自訂比例及收入類型篩選。
預計薪資、跨期收入平滑、週／年收入聯動與按比例自動重分配分類，列為後續擴充。

## 3. 產品規則與金額定義

### 3.1 模式

- 預設維持手動模式；舊帳戶不會自動啟用收入聯動。
- 收入模式只影響每月總預算的資金計算；每週、每年仍沿用手動規則。
- 類別金額、預算歷史及結轉設定保留；收入變動不會自動改寫分類。
- 設定入口放在現有總預算設定中，沿用既有按鈕及表單設計，避免建立重複入口。
- 已保存的手動上限與聯動設定分開儲存，切回手動模式時明確顯示採用的金額。

### 3.2 計算

所有運算使用 MYR 最小貨幣單位；比例轉為整數基點，避免多次浮點加總。

```text
本期可計入收入 I = 本帳期中、截至今日、符合類型規則的收入 MYR 合計
收入支持額度 F = round(I × 預算比例基點 / 10000)
預留金額 R = I − F
已分配金額 A = 現有 monthly 分類預算設定的基本分配合計
尚可分配 U = max(F − A, 0)
資金缺口 G = max(A − F, 0)
```

比例允許 0%–100%，最多兩位小數；超出範圍、空白或非有限數值不可保存。
每筆金額及合計的最小貨幣單位均須為安全整數；負值、無效日期或加總溢位應進入需處理狀態，不靜默丟棄資料。
零收入且資料完整時顯示零額度，不能以「尚未設定」或讀取失敗取代零。
資金缺口可以存在；不得用 `max(F, A)` 冒充收入支持額度。

例如收入 RM5,000、比例 80%、分類已分配 RM3,200：額度 RM4,000、預留 RM1,000、尚可分配 RM800。
若收入改為 RM3,000：額度 RM2,400、已分配仍為 RM3,200、缺口 RM800。
若分類增加 RM1,000：收入不變，尚可分配或缺口隨分配重新計算。

「尚可分配」與「扣除實際支出後的預算餘額」分開顯示。
分類結轉是過往額度，不直接算成當期收入；首版的 A 採基本分類分配，結轉另列。
此定義沿用 `getAllocatedBudgetMinorUnits`：分類是持續生效的預算設定，不是假設每月另存一份歷史版本；不在此功能中偷偷改變現有 startDate 的分配語意。
若未來要把結轉視為資金來源，必須獨立記錄來源，避免重複計入收入。

### 3.3 收入來源與排除

| 資料 | 預設 | 規則 |
| --- | --- | --- |
| `Income.type = salary` | 計入 | 依入帳日期與已儲存匯率快照 |
| `Income.type = other` | 計入 | 說明此類型可能包含使用者自訂收入 |
| `Income.type = reimbursement` | 排除 | 可選擇計入；說明可能只是費用回收 |
| `Income.type = repayment` | 排除 | 開啟後只計入收入主帳中的此類記錄，包含另建的超額收入；不加總還款集合 |
| `Income.category = ewallet_reload` | 永遠排除 | 即使類型為 salary／other 也先排除 |
| `Transfer` | 永遠排除 | 自有帳戶移轉不產生新收入 |
| 獨立 `Repayment` 集合 | 不自動合併 | 既有支出淨額已扣還款，缺少同一事件的唯一關聯時不可再次加進收入 |
| 未來日期／其他帳號資料 | 排除 | 預計收入不視為已入帳 |

首版的唯一收入來源是 `incomes`；`includeRepayments` 的文案必須說明它控制的是收入主帳的還款／超額收入，不是把所有朋友還款再計入一次。
透過穩定收入 ID 去重，不跨集合猜測日期／金額的相同事件。若未來要計入完整 `repayments`，須先增加可驗證的來源關聯及對支出淨額的單一計算規則。
現有超額收入建立仍在還款頁以非原子、直接服務呼叫處理，具有離線及並行一致性風險。此功能不能新增同類寫入；若改動這條產生路徑，必須一併使用穩定 ID、outbox、原子 receipt 和來源關聯，並補相應測試。

## 4. 帳期、資料完整性與匯率

- 以帳單週期為每月邊界，不用收入列表目前的月份篩選條件。
- 週期以當地日期比較，起日包含、下期起日不包含；資料查詢的含尾日為下期起日前一天。
- 今日之後的收入不計入已入帳額度；跨午夜、跨期、重新回到頁面時重算日期範圍。
- 29–31 日在短月截斷到該月最後一天。例：31 日帳期在非閏年應依次為 1/31、2/28、3/31。
- 共用帶邊界測試的日期函式；不能讓收入、總預算及分類預算使用互相不一致的月底處理。
- 查詢需完整遍歷指定帳期並用穩定日期＋文件 ID 游標；加總不能只使用 UI 已載入的 100 筆。
- 重用同範圍並行讀取，舊讀取結果不能覆蓋較新的本機收入；收入變動時只失效對應的衍生讀取。
- 先合併待同步操作，再依帳號、類型與週期過濾，讓日期被修改而移入／移出帳期的收入正確反映；不能只把目前畫面資料加到區間查詢結果。
- 區間結果必須保存其範圍及完整性，不能覆寫共用集合快取後將局部內容標為 `all`，也不能丟掉其他列表所需的歷史資料。
- 離線時只有涵蓋整個帳期且版本穩定的快取可標為完整。快取不足時顯示「資料未完整」，不報確定的可分配數字。
- 以已入帳時保存的 MYR 估值計算，顯示貨幣轉換僅影響呈現；匯率每天變動不能悄悄改寫歷史收入支持額度。
- 非 MYR 的 `baseCurrency` 不能直接當 MYR 加總；缺少正確估值時顯示需修正的資料狀態，不能當作零收入。

## 5. 建議資料與寫入設計

建議在 `UserSettings` 新增以下可選設定（新 schema 的精確型別與 rules 須保持相同）：

```ts
incomeLinkedBudget?: {
  version: 1;
  enabled: boolean;
  percentage: number; // 0–100，最多兩位小數
  includeReimbursements: boolean;
  includeRepayments: boolean; // 僅控制 Income.type，不讀取還款集合作為額外收入
};
```

初次開啟表單可建議 80%，此數字只是可編輯預填值，不自動開啟功能。
缺少欄位代表手動模式；不批次改寫既有收入或分類預算。
純計算結果採用明確的 `ready | loading | incomplete | invalid | error` 狀態；僅 ready 具有可發布金額，其他狀態帶原因及可重試資訊。
非法或未知版本的遠端設定不能靜默啟用聯動；顯示需處理狀態並保留舊手動設定。

收入支持額度是「設定＋完整收入快照」的衍生結果，不在每次 render、每次收入修改時寫回 `overallBudgetLimits`。
收入的新增／修改／刪除繼續由原收入交易處理帳戶餘額及 receipt；純計算不產生第二次餘額調整。

新設定的保存流程：

1. 驗證設定、使用者擁有者、穩定 singleton 文件 ID。
2. 建立樂觀畫面，同時等待完整設定操作持久化到 IndexedDB outbox。
3. 持久化成功後才關閉儲存視窗並宣告「已儲存在此裝置」；遠端同步狀態另列。
4. 由 syncService 以跨分頁 claim 與 fencing 執行；設定與 immutable mutation receipt 在同一交易提交。
5. 遠端永久錯誤保留待處理操作，顯示重試／處理入口；儲存裝置失敗則不宣告接受。

模式切換與分類分配使用相同 budget-allocation 依賴與 revision 保護。
收入模式的分類操作不能自動提高收入支持額度；超額要在確認前預覽缺口，提交後保留缺口提醒。
收入模式的預算交易需略過手動 monthly 上限自動提高分支，但仍驗證金額、擁有者及修訂版號；不能刪除原手動上限，也不能略過 weekly／yearly 的手動驗證。
切回手動模式時，若舊手動上限低於現有分配，須先選擇一個不低於分配的手動金額，並在同一設定交易完成切換。
設定競態以交易內重讀為準；重播不重新套用已確認的舊模式／舊金額。

建議新增專用的 `setIncomeLinkedBudget` 設定命令，而非讓任意一般設定 patch 繞過模式切換驗證。
命令攜帶完整設定及切回手動時選定的上限，使用者 singleton ID、operation ID 與上一版本快照；在同一 `runBudgetMutationTransaction` 中讀取最新分類、驗證、修改設定、遞增 revision 並寫 receipt。
本機 overlay 與 syncService 解析同一命令，dependencyKeys 同時加入 userSettings 文件鍵和 budget-allocation 鍵。
純收入增減仍只有原收入操作，不另入列「重算總預算」。

相容性要求分開驗證：舊帳號／手動模式維持原行為；已啟用收入模式的帳號，舊客戶端若企圖自動提高手動 monthly 上限，rules 應安全拒絕該不相容修改，保留可處理的 pending 操作。
不能為了讓舊客戶端所有修改都成功，而允許它覆寫收入模式或保存的手動上限；新客戶端需提示使用更新版本處理。

## 6. UI 與刷新

- 總預算視窗提供「固定金額／依收入比例」，收入模式顯示比例、收入類型與當期預覽。
- 摘要顯示本期收入、預算比例、收入支持額度、預留、分類分配、尚可分配／缺口及實際支出餘額。
- 空資料、載入中、範圍不完整、估值錯誤、本機待同步、需處理錯誤使用不同訊息。
- 缺口用文字和金額說明，不能只靠紅色；輸入欄位有標籤，錯誤使用可讀的提示。
- 收入模式增加分類時，先提示此操作產生的缺口；不顯示手動模式的「總預算已自動提高」訊息。
- 儀表板、總預算頁和相關摘要共用同一 selector，避免兩個頁面金額不同。
- 收入 mutation／設定變更／同步結果透過既有資料事件更新；不加 storage polling，不逐筆刷新整個 dashboard。
- 同一帳號跨分頁同步設定；切換帳號立即清除前帳號的衍生值與讀取結果。
- 本機已接受但待同步的收入可用於明確標記的本機預覽；存在永久拒絕／需處理操作時，不能把其結果顯示為伺服器已確認的可用資金。
- 完整補上英文、繁體、簡體文案，沿用現有 PopupModal 及按鈕樣式。

## 8. 必須具備的驗收證據

| 情境 | 預期結果 |
| --- | --- |
| 舊帳號沒有新設定 | 保持手動金額與原有分類，不自動遷移 |
| 收入 5000、80%、分配 3200 | 額度 4000、預留 1000、尚可分配 800 |
| 收入降低為 3000 | 額度 2400、分配仍 3200、缺口 800 |
| 收入／比例增加 | 只改資金預覽，不自動改分類金額 |
| 新分類超出聯動額度 | 確認前提示缺口，儲存後收入支持額度不被提高 |
| 0%、100%、兩位小數與不合法比例 | 邊界正確，非法值在本機及 rules 均拒絕 |
| 薪資、其他、儲值、轉帳、報銷、還款 | 按來源規則計入，儲值與轉帳不增加收入 |
| 普通還款＋另建超額收入同時存在 | 永不加總普通還款；只按選項計入收入主帳的超額部分一次 |
| 日期移入／移出帳期及未來日期 | 只計入截至今日的本期收入 |
| 31 日帳期、閏年 2 月、跨年 | 邊界不溢位、不漏日、不重複計入 |
| 超過一頁的收入與同日同金額資料 | 完整遍歷，依穩定 ID 去重，金額不受 UI 分頁影響 |
| 收入有外幣、舊 MYR 或缺失匯率 | 正確使用已入帳估值；無法估值時不聲稱完整 |
| 入列前儲存失敗 | 顯示錯誤，沒有本機接受或已同步的假訊息 |
| 離線保存、重載、收入接續編輯／刪除 | 設定與收入最新意圖持續可見，依序同步 |
| 提交成功但回應遺失／跨分頁重播 | receipt 防重複，舊工作者不能覆寫新設定，不重複改餘額 |
| 永久遠端拒絕 | 保留操作與可恢復錯誤，衍生資料標明需處理 |
| 切換帳號／讀取期間修改收入 | 不顯示前帳號資料，不發布已過期的加總 |
| 切回手動、同時另一分頁新增分類 | 同一 revision 交易驗證，手動上限不低於分配 |
| 完整快取／不完整快取 | 前者可離線計算，後者標明不足且不給確定可分配額 |
| 儀表板及預算頁、手機及桌面 | 相同帳期與金額，操作入口與設計一致 |

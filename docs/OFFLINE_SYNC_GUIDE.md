# 本機先顯示與同步使用說明

> 狀態說明核對至 `main@9fce5d7`。app queue 由 IndexedDB 保存；Firebase SDK 自己的 IndexedDB pending writes 是另一條路徑。此次 main UI 樣式更新未改變這些保存/同步行為。任何「已儲存在此裝置 / 已儲存離線」提示都應表示該操作已通過本機 outbox 持久化，而單純的列表即時更新不代表 queue 已接受。

## 操作結果怎麼看

- 新增、編輯或刪除成功送出後，畫面會先更新，表單不必等待 Firebase 才能讓清單刷新。
- 符合本機接受條件的操作會先保存到目前瀏覽器 IndexedDB app queue，再由 `syncService` 在背景同步，不必等待遠端完成才回報本機接受。同步途中重新整理，待同步資料仍會重新套用；同一帳戶依送出順序處理。各功能是否走此路徑，依該功能的成功/離線提示和[同步覆蓋說明](LOGIC_METHOD_FLOW.md)判斷。
- 「已儲存離線」表示操作已寫入本機 app queue，尚未代表 Firebase 已同步。
- Dashboard 的待同步數字只計算 app queue，不包含 Firestore SDK 自己管理的 IndexedDB 待同步寫入。
- 權限錯誤、資料驗證錯誤或預算限制錯誤不屬於網路中斷；操作會回復或顯示錯誤，不會被當作可重試的離線寫入。

## 手動同步

網路恢復後，應用會自動嘗試同步。也可點頁首待同步數字，或在漢堡選單按「重新上傳」。按鈕會執行 queue sync；完成後仍顯示的筆數代表尚未同步或需要處理的操作。

若某項操作達到重試上限，queue 會保留為需處理狀態，畫面可提供重試入口。確認網路和目前登入帳戶後再重試；其他帳戶的操作會留在本機，等原帳戶登入再處理。最大重試次數目前為 5；錯誤/驗證拒絕可能使用 entity 專屬回復流程。

## 清除佇列

「清除佇列」會永久刪除目前瀏覽器的所有 app queue 操作，不能復原，也不會清除 Firestore SDK 的 IndexedDB 待同步資料。清除後，佇列中尚未同步的新增、更新或刪除沒有補救方式。只有確認所有待處理操作都可丟棄時才使用。

整體預算限額需要即時伺服器驗證配置；歷史匯率缺失時也無法安全保存多幣別資料。這些情況會顯示驗證/同步錯誤，不會被誤報為已保存離線。技術流程請見[本機優先與 Firebase 同步架構](OFFLINE_SYNC_ARCHITECTURE.md)及[邏輯與 Method 流程](LOGIC_METHOD_FLOW.md)。

「已儲存於本機」、「同步中」、「雲端已確認」和「需要處理」是不同狀態，不能以同一個成功提示代替；視覺候選見 [UI 同步回饋模式](ui-standardization/INTERACTION_PATTERN_CANDIDATES.md)。
